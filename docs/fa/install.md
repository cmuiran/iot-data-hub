# راهنمای نصب روی سرور ویندوز

این راهنما برای یک سرور Windows Server 2019/2022 (یا ویندوز ۱۰/۱۱ نسخهٔ Pro/Enterprise) نوشته شده است.
همهٔ مراحل را با حساب مدیر انجام دهید. مقادیر داخل `<...>` را با مقادیر سایت جایگزین کنید.

## ۱. پیش‌نیازها

| مورد | حداقل | توصیه |
|---|---|---|
| CPU / RAM | ۴ هسته / ۸ گیگابایت | ۸ هسته / ۱۶ گیگابایت |
| دیسک | ۱۰۰ گیگابایت SSD | دیسک جدا برای داده و پشتیبان |
| شبکه | یک کارت در شبکهٔ OT (دستگاه‌ها) | دو کارت: OT و شبکهٔ اداری، بدون مسیریابی بین آن‌ها |
| ساعت | همگام با NTP | سرور زمان دامنه یا سرور NTP داخلی |

نرم‌افزارها (نصب با مدیر IT؛ فایل‌ها را فقط از سایت رسمی سازنده دریافت کنید):

* Python 3.12 (64 بیتی، گزینهٔ «Add to PATH»)
* PostgreSQL 17 (نصب‌کنندهٔ EnterpriseDB)
* TimescaleDB برای PostgreSQL 17 (اختیاری ولی توصیه‌شده؛ برای نگهداری سبک تاریخچه)
* WinSW-x64 نسخهٔ ۲٫۱۲ یا بالاتر (برای سرویس ویندوز)

## ۲. پایگاه داده

۱. PostgreSQL را نصب کنید. گذرواژهٔ کاربر `postgres` را در گاوصندوق رمز سازمان نگه دارید.

۲. TimescaleDB را نصب کنید: `setup.exe` آن را با «Run as administrator» اجرا کنید و سرویس PostgreSQL را دوباره راه بیندازید.

۳. در `psql` (یا pgAdmin) یک کاربر و یک پایگاه داده بسازید:

```sql
CREATE ROLE hub_app LOGIN PASSWORD '<گذرواژه قوی>';
CREATE DATABASE hub OWNER hub_app;
-- برای «تست بازیابی کامل» پشتیبان‌ها (HUB_RESTORE_TEST=full):
ALTER ROLE hub_app CREATEDB;
```

۴. PostgreSQL فقط باید روی `localhost` گوش بدهد. اگر دو نود (HA) دارید، فقط IP نود دیگر را در `pg_hba.conf` مجاز کنید.

## ۳. نصب برنامه

### راه توصیه‌شده: بستهٔ آفلاین و نصب‌کنندهٔ خودکار

شبکهٔ سایت معمولاً به اینترنت دسترسی ندارد، پس بسته روی یک سیستم دیگر ساخته می‌شود.

۱. روی یک سیستم ویندوزی که اینترنت دارد (با Python 3.12)، در پوشهٔ پروژه بسته را بسازید:

```
powershell -ExecutionPolicy Bypass -File scripts\windows\build-bundle.ps1
```

خروجی `release\iot-data-hub-<نسخه>-windows.zip` و فایل `.sha256` آن است. بسته شامل این‌هاست:
* برنامه
* پوشهٔ `wheelhouse` با همهٔ وابستگی‌ها، دقیقاً همان نسخه‌های `requirements.lock`
* نمونهٔ پیکربندی (`config.dist`)
* فایل `SHA256SUMS.txt`

۲. این فایل‌ها را به سرور منتقل کنید:
* فایل zip و `.sha256`
* نصب‌کنندهٔ Python 3.12
* `WinSW-x64.exe`

۳. درستی فایل را بررسی کنید. خروجی دستور زیر باید با محتوای فایل `.sha256` یکی باشد:

```
Get-FileHash .\iot-data-hub-<نسخه>-windows.zip -Algorithm SHA256
```

۴. بسته را باز کنید، مثلاً در `D:\hub`. فایل WinSW را با نام `scripts\windows\hub-api-service.exe` در همان پوشه بگذارید.

۵. پایگاه داده را طبق بخش ۲ آماده کنید.

۶. در PowerShell با دسترسی مدیر اجرا کنید:

```
cd D:\hub
powershell -ExecutionPolicy Bypass -File scripts\windows\install.ps1 -DatabaseUrl "postgresql://hub_app:<گذرواژه>@localhost:5432/hub" -AdminUser <نام مدیر>
```

نصب‌کننده این کارها را انجام می‌دهد:
* ساخت محیط Python به‌صورت آفلاین
* ساخت `config\` از نمونه‌ها
* ساخت `‎.env` با `HUB_JWT_SECRET` و `HUB_DATA_KEY` تصادفی (این مقادیر هیچ‌جا نمایش داده نمی‌شوند)
* محدود کردن دسترسی `‎.env` به Administrators و SYSTEM
* بررسی پیکربندی و ساخت جدول‌های پایگاه داده
* ساخت مدیر اول (گذرواژه پرسیده می‌شود)
* نصب سرویس ویندوز

فرمان از راه دور خاموش می‌ماند. اجرای دوباره نصب‌کننده بی‌خطر است: هر مرحله‌ای که قبلاً انجام شده رد می‌شود.

**پس از نصب، یک نسخه از `HUB_DATA_KEY` (داخل `‎.env`) را در گاوصندوق رمز سازمان نگه دارید.**

### نصب دستی (با اینترنت)

```
cd D:\hub
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.lock
.venv\Scripts\python.exe -m pip install --no-deps -e .
```

پس از نصب دستی، بخش‌های ۴ تا ۷ را خودتان انجام دهید.

### روی لینوکس با Docker (برای سایت‌های بزرگ)

اگر بیش از حدود ۴۰۰ دستگاه با IP جداگانه دارید، این روش را انتخاب کنید (بخش ۱۲ را ببینید).
روی یک سرور لینوکس با Docker:

```
cp .env.example .env        # HUB_JWT_SECRET، HUB_DATA_KEY، POSTGRES_PASSWORD و رمز دستگاه‌ها
docker compose up -d
docker compose exec hub hub-admin create-admin --username <نام مدیر>
```

PostgreSQL و TimescaleDB هم در همین Compose اجرا می‌شوند. پیکربندی در پوشهٔ `config/` کنار `docker-compose.yml` قرار دارد.

## ۴. فایل ‎.env (رمزها و تنظیمات)

`‎.env.example` را به `‎.env` کپی کنید و دست‌کم این‌ها را پر کنید:

| متغیر | مقدار |
|---|---|
| `HUB_DATABASE_URL` | `postgresql://hub_app:<گذرواژه>@localhost:5432/hub` |
| `HUB_JWT_SECRET` | رشتهٔ تصادفی بلند (دست‌کم ۴۰ نویسه) |
| `HUB_DATA_KEY` | رشتهٔ تصادفی بلند دیگر. پشتیبان‌ها و MFA با آن رمز می‌شوند. **یک نسخه را جدا و امن نگه دارید** |
| `HUB_HOST` / `HUB_PORT` | `0.0.0.0` و پورت (پیش‌فرض 8000) برای دسترسی از شبکه |
| `HUB_TLS_CERT` / `HUB_TLS_KEY` | گواهی HTTPS (بخش ۶) |
| `HUB_CONTROL_ENABLED` | **`false`** تا پایان راه‌اندازی و تست فرمان |
| `HUB_TIMEZONE` | `Asia/Tehran` |
| `HUB_BACKUP_DIR` | مثلاً `E:\hub-backups` (دیسکی غیر از دیسک داده) |
| `HUB_NTP_SERVER` | سرور زمان سایت، مثلاً کنترلر دامنه |
| رمز دستگاه‌ها | فقط نام متغیرهایی که در فایل دستگاه آمده‌اند، مثل `HUB_OPCUA_PLC01_PASSWORD` |

قانون: هیچ رمزی در فایل‌های `config\` یا کد نوشته نمی‌شود. فایل‌های دستگاه فقط **نام** متغیر محیطی را دارند.
دسترسی فایل `‎.env` را به حساب سرویس و مدیران محدود کنید (Properties → Security).

## ۵. آماده‌سازی و اولین اجرا

```
.venv\Scripts\python.exe -m hub.validate_config
.venv\Scripts\hub-admin.exe create-admin --username <نام مدیر>
.venv\Scripts\hub-api.exe
```

`create-admin` جدول‌های پایگاه داده را هم می‌سازد. سپس مرورگر را روی `https://<سرور>:<پورت>/` باز کنید و وارد شوید.
در اولین ورود باید گذرواژه را عوض کنید. سپس با Ctrl+C برنامه را ببندید و سرویس را نصب کنید.

## ۶. HTTPS

* با گواهی CA سازمان (بهترین راه): مسیر فایل‌های PEM را در `HUB_TLS_CERT` و `HUB_TLS_KEY` بگذارید.
* بدون CA: `hub-admin make-tls-cert --name hub.kish.local --name <IP سرور>` یک گواهی خودامضا می‌سازد.
  فایل `.crt.pem` را در «Trusted Root» رایانه‌های اپراتور وارد کنید.
* هشدار انقضای گواهی ۳۰ روز پیش از موعد به‌صورت هشدار سیستمی می‌آید.

## ۷. سرویس ویندوز

۱. `WinSW-x64.exe` را با نام `scripts\windows\hub-api-service.exe` ذخیره کنید.

۲. در PowerShell با دسترسی مدیر، در پوشهٔ برنامه:

```
powershell -ExecutionPolicy Bypass -File scripts\windows\install-service.ps1
```

* برای اجرا با حساب سرویس دامنه: `-Account "DOMAIN\svc-hub"`.
* اسکریپت پیکربندی را بررسی می‌کند، سرویس را نصب و اجرا می‌کند و آن را روی «راه‌اندازی مجدد پس از خطا» می‌گذارد.
* حذف سرویس: `scripts\windows\uninstall-service.ps1`.
* وضعیت سرویس: `Get-Service hub-api`. سلامت: `https://<سرور>:<پورت>/api/health` باید `ok` بدهد.

## ۸. فایروال

| جهت | پورت | از / به | دلیل |
|---|---|---|---|
| ورودی | پورت HTTPS هاب | شبکهٔ اپراتورها | داشبورد و API |
| ورودی | 4840 (اگر سرور OPC UA روشن است) | فقط SCADA | خواندن داده توسط SCADA |
| ورودی | 502 / پورت سرور Modbus (اگر روشن است) | فقط HMI/PLC مشخص | |
| خروجی | 502، 102، 4840، 1883/8883، 161، 80/443 | فقط IP دستگاه‌ها در شبکهٔ OT | پروتکل‌های میدانی |
| خروجی | 587 / 443 | سرور ایمیل، تلگرام، درگاه پیامک | اعلان‌ها |
| خروجی | 514 / 601 | SIEM (اگر دارید) | لاگ امنیتی |

در `HUB_ALLOWED_NETWORKS` هم زیرشبکه‌های مجاز (مثلاً `10.10.0.0/16`) را بنویسید.

## ۹. پشتیبان و بازیابی

* هاب هر شب در `HUB_BACKUP_TIME` پشتیبان می‌گیرد. اگر `HUB_DATA_KEY` باشد، فایل رمز می‌شود.
  `HUB_BACKUP_KEEP` نسخهٔ آخر نگه داشته می‌شود.
* هر پشتیبان خودکار آزمایش می‌شود (`HUB_RESTORE_TEST=archive`). با `full` هر ۷ روز یک بار
  پشتیبان در یک پایگاه موقت بازیابی و بررسی می‌شود.
* پوشهٔ پشتیبان را روزانه به یک مکان دیگر (NAS یا سرور پشتیبان) کپی کنید.
* بازیابی: سرویس را متوقف کنید، سپس `hub-admin restore-backup <فایل> --yes` و سرویس را دوباره روشن کنید.
* پوشهٔ `config\` را در git یا یک مخزن نسخه‌دار نگه دارید.

## ۱۰. ساعت سرور

برچسب زمانی همهٔ داده‌ها و لاگ‌ها از ساعت سرور است. ویندوز را روی سرور زمان سایت تنظیم کنید
(`w32tm /config /manualpeerlist:<سرور> /syncfromflags:manual /update`).
`HUB_NTP_SERVER` را هم بگذارید تا اختلاف ساعت بیش از ۳۰ ثانیه هشدار `system:clock` بدهد.

## ۱۱. پس از نصب

| بررسی | روش |
|---|---|
| سرویس بالا است | `Get-Service hub-api` → Running |
| سلامت | صفحهٔ «سیستم» → «سلامت هاب»: همه سبز |
| پشتیبان | فردای نصب: صفحهٔ «سیستم» → آخرین پشتیبان و نتیجهٔ تست بازیابی |
| آمادگی ارتقا | `hub-admin upgrade-check` |

سپس راه‌اندازی دستگاه‌ها را طبق [commissioning.md](commissioning.md) انجام دهید.

## ۱۲. ظرفیت یک هاب

| محدودیت | مقدار | اگر بیشتر لازم است |
|---|---|---|
| حجم داده | حدود ۵۰۰۰ نمونه در ثانیه برای یک هاب (یک هستهٔ CPU)، مثلاً ۲۵۰ دستگاه × ۲۰ تگ با پرسش هر ۱ ثانیه، یا ۱۲۵۰ دستگاه × ۲۰ تگ با پرسش هر ۵ ثانیه | پرسش کندتر (`poll_interval_ms`)، یا تقسیم دستگاه‌ها بین دو هاب |
| اتصال‌های شبکه روی ویندوز | حداکثر ۴۰۰ اتصال دستگاه. هر دستگاه با IP جدا یک اتصال است؛ دستگاه‌های پشت یک گیت‌وی Modbus روی هم یک اتصال حساب می‌شوند | گیت‌وی، لینوکس (Docker)، یا دو هاب |

`python -m hub.validate_config` از ۳۲۰ اتصال به بالا هشدار می‌دهد و از ۴۰۰ به بالا خطا می‌دهد، تا هاب در بهره‌برداری از کار نیفتد.
برای اندازه‌گیری روی سخت‌افزار خود سایت:

```
.venv\Scripts\hub-loadtest.exe --devices 300 --tags 20 --seconds 180
```

این تست فقط با شبیه‌ساز کار می‌کند و به هیچ دستگاه واقعی وصل نمی‌شود. آن را روی پایگاه دادهٔ بهره‌برداری اجرا نکنید.
